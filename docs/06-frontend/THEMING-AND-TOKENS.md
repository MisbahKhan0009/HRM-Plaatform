# Theming and tokens

Brand tokens flow one way: `docs/02-brand/source/tokens.json` (snapshot of the owner's design system) → generated CSS variables in `packages/ui/tokens/` → Tailwind v4 theme in `packages/ui/styles/` → components. Nobody types a brand value by hand. **Ink (dark) is the default theme; users can switch to Paper (light)** (D-040, `docs/02-brand/APP-UI-ADAPTATION.md`).

## 1. Token generation

Script: `packages/ui/scripts/build-tokens.ts`, run by `pnpm --filter @hrm/ui tokens` and in CI (fails if the generated files differ from what's committed).

Input: `docs/02-brand/source/tokens.json` plus `packages/ui/tokens/app-tokens.json`, which holds the app additions from APP-UI-ADAPTATION.md section 4 (`warn`, `warn-tint`) and COMPONENT-SPECS.md section 1.1 (`control-border`), in the same `{ name, value: { ink, paper }, usage }` shape.

Output: `packages/ui/tokens/tokens.css`:

```css
/* generated by build-tokens.ts from docs/02-brand/source/tokens.json; do not edit */
:root,
[data-theme="ink"] {
  --ground: #0f1011;
  --surface: #1c1f22;
  --text: #f1f2f3;
  /* … every role colour with its Ink value … */
  --glow-a: 0.4;   /* glow-ink */
  --glow-b: 0.16;  /* glow-2-ink */
  color-scheme: dark;
}
[data-theme="paper"] {
  --ground: #ffffff;
  --surface: #ffffff;
  --text: #1c1c1c;
  /* … Paper values … */
  --glow-a: 0.14;  /* glow-paper */
  --glow-b: 0.07;  /* glow-2-paper */
  color-scheme: light;
}
:root {
  /* theme-independent tokens */
  --bm-accent: #ec362e;
  --bm-r: 6px; --bm-r-lg: 10px; --bm-r-pill: 999px;
  --space-4: 4px; /* … */
  --focus-width: 2px; --focus-offset: 2px;
  --grid-pitch: 22px; --grid-dot-radius: 1px;
  --shadow-primary: 0 10px 28px -12px rgba(236, 54, 46, 0.7);
  --bm-gradient-emphasis: linear-gradient(98deg, #f4564e 0%, #ec362e 34%, #c62519 100%);
  --font-display: "Inter Tight", Arial, sans-serif;
  --font-body: "Inter", Arial, sans-serif;
  --font-mono: "JetBrains Mono", Consolas, monospace;
}
```

Rules of the generator:

- Aliases (`{bm-ink}`) are resolved to values; a missing alias fails the build.
- Ink is written first and also on `:root`, so a page with no `data-theme` renders Ink.
- `color-scheme` is set per theme so native controls (scrollbars, date inputs) match.
- `bm-*` brand constants are emitted on `:root` for the few brand components that need them (Glow uses `--bm-accent`). Product components use role tokens only.

## 2. Tailwind v4 theme

`packages/ui/styles/theme.css` maps CSS variables into Tailwind utilities with `@theme inline`, so classes read variables at runtime and switch with `data-theme`:

```css
@import "tailwindcss";
@import "../tokens/tokens.css";

@custom-variant paper (&:where([data-theme="paper"], [data-theme="paper"] *));

@theme inline {
  --color-ground: var(--ground);
  --color-ground-2: var(--ground-2);
  --color-surface: var(--surface);
  --color-text: var(--text);
  --color-text-2: var(--text-2);
  --color-text-3: var(--text-3);
  --color-line: var(--line);
  --color-line-strong: var(--line-strong);
  --color-control-border: var(--control-border);
  --color-accent: var(--accent);
  --color-accent-tint: var(--accent-tint);
  --color-accent-text: var(--accent-text);
  --color-link: var(--link);
  --color-action: var(--action);
  --color-action-hover: var(--action-hover);
  --color-on-action: var(--on-action);
  --color-ok: var(--ok);   --color-ok-tint: var(--ok-tint);
  --color-bad: var(--bad); --color-bad-tint: var(--bad-tint);
  --color-warn: var(--warn); --color-warn-tint: var(--warn-tint);
  --font-display: var(--font-display);
  --font-sans: var(--font-body);
  --font-mono: var(--font-mono);
  --radius-bm: var(--bm-r);
  --radius-bm-lg: var(--bm-r-lg);
  --radius-pill: var(--bm-r-pill);
  --shadow-primary: var(--shadow-primary);
}
```

- Tailwind's default palette is disabled (`--color-*: initial;` before the mapping) so only brand colours exist as classes.
- Spacing uses Tailwind's 4px base (`p-4` = 16px), which matches the brand's 4px scale. Use only values on the brand scale: 1, 2, 3, 4, 6, 8, 12, 16, 24 (4px to 96px).
- There is no `dark:` variant in use. Theme differences live in the variables; components don't branch on theme. The `paper:` variant exists for rare exceptions (logo file choice) and needs a review comment when used.

## 4. Theme selection and persistence

Precedence (APP-UI-ADAPTATION.md section 1): **server preference → `localStorage` → Ink**. The OS `prefers-color-scheme` is ignored.

### 4.1 No-flash script

`apps/web/index.html` runs a tiny inline script before CSS paints:

```html
<script>
  try {
    var t = localStorage.getItem('hrm.theme');
    document.documentElement.dataset.theme = t === 'paper' ? 'paper' : 'ink';
  } catch (e) {
    document.documentElement.dataset.theme = 'ink';
  }
</script>
```

The script is static (no user data), so it is allowed by the Content Security Policy through a hash (`docs/08-operations/` owns the CSP header).

### 4.2 After sign-in

1. `GET /auth/me` returns `theme` (`ink` or `paper`).
2. If it differs from the current `data-theme`, apply it and write it to `localStorage` (`hrm.theme`). The server value wins, so the choice follows the user across devices.

### 4.3 Toggling

1. Set `document.documentElement.dataset.theme` immediately.
2. Write `localStorage`.
3. `PATCH /auth/me/preferences` with `{ theme }`; update the `['auth','me']` cache from the response. On failure, keep the local change and show a toast "Couldn't save your theme. It will apply on this device only." No rollback.

Signed-out pages (auth zone) use `localStorage` only.

### 4.4 Logo per theme

`<Logo />` chooses `bms-logo-full-dark` (white lettering) on Ink and `bms-logo-full-light` (Graphite lettering) on Paper by reading the theme from context; both SVGs are imported as assets from `packages/ui/brand/logos/` (copied from `docs/02-brand/source/logos/`). The payslip PDF always uses the light lockup on white.

## 5. Fonts

- Inter, Inter Tight and JetBrains Mono, all free (SIL Open Font License) on Google Fonts. The variable `woff2` files (Latin subset) are copied from the brand source into `packages/ui/styles/fonts/` and **self-hosted**, so there are no requests to Google at runtime (privacy and offline dev).
- `@font-face` with `font-display: swap`, `font-weight` ranges for the variable axes, and `<link rel="preload">` for Inter (body) only.
- Bangla text later needs a Bengali-capable face. Inter has no Bengali glyphs, so I18N.md section 6 adds a free fallback (Noto Sans Bengali) to the stack when Bangla ships.
- Numbers in tables and money use `font-variant-numeric: tabular-nums` (utility class `tabular-nums`).

## 6. Focus ring

Global base style in `packages/ui/styles/base.css`:

```css
:where(a, button, input, select, textarea, [tabindex]):focus-visible {
  outline: var(--focus-width) solid var(--accent);
  outline-offset: var(--focus-offset);
}
```

Components must not remove outlines. Inputs with an inset look still use this outer outline.

## 7. Signature elements

`DotGrid` and `Glow` (from `packages/ui/brand/`) follow the brand CSS in `docs/02-brand/source/components/bundle.css`, reading `--grid-dot`, `--grid-pitch`, `--grid-dot-radius`, `--bm-accent`, `--glow-a`, `--glow-b`. Use them only where COMPONENT-SPECS.md section 23 allows. Both are `aria-hidden` and `pointer-events: none`.

## 8. Adding or changing a token

1. Brand change: the owner updates the design-system artifact; someone re-syncs `docs/02-brand/source/` (see its README), then runs the token script.
2. App-only token: add it to `app-tokens.json` with both theme values and a usage note, measure contrast and add it to `docs/04-design/ACCESSIBILITY.md` section 3, and record it in `docs/02-brand/APP-UI-ADAPTATION.md`.
3. Never add a token for a one-off; reuse a role.
