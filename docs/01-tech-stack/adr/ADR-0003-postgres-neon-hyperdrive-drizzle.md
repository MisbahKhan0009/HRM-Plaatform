# ADR-0003: PostgreSQL (Neon) via Hyperdrive, Drizzle ORM

- Status: Accepted (2026-10-22)

## Context
SRS requires atomic leave approval + ledger posting (FR-LEAVE-009), concurrency-safe balances (FR-LEAVE-013), transactional idempotent payroll locking (FR-PAY-019), `NUMERIC` money, case-insensitive unique emails and FK protection of history. Cloudflare D1 (SQLite) lacks interactive transactions and row locks.

## Decision
- **Neon** serverless Postgres (Singapore region, closest to Bangladesh) — branching per PR/staging, point-in-time restore.
- **Hyperdrive** for connection pooling and low latency from Workers; `postgres`/`pg` driver.
- **Drizzle ORM** with SQL migrations generated by `drizzle-kit` and committed (NFR-MNT-003).
- Use `SELECT … FOR UPDATE`, unique constraints and an `idempotency_records` table for critical operations.
- `citext` (or `lower()` unique index) for emails; `ON DELETE RESTRICT` for financial/audit FKs.

## Consequences
+ Full relational integrity; PITR covers RPO ≤ 24h requirement (NFR-OPS-005) with large margin.
− External dependency outside Cloudflare; Neon outage = app outage. Backups additionally exported nightly to R2 (`pg_dump`) via scheduled GitHub Action.
